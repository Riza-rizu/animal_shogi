# 千日手防止機構：幾何減衰型レピティション・ペナルティ 仕様書

**作成日:** 2026-10-19  
**対象プロジェクト:** どうぶつ将棋 強化学習パイプライン (`animal_shogi`)  

---

## 1. 背景と課題

### 1.1 従来の課題（千日手ループの発生）
従来の自己対局および探索（Min-Max `depth=2`）において、以下の力学により同一局面の往復（千日手）が多発していた：
- **攻め側（優勢側）**: 局面を維持する手が最も評価が高く（例: $+0.4$）、自発的に同じ局面に戻す手を選び続ける。
- **受け側（劣勢側）**: 他の手を選ぶと即死（$-1.0$）するため、唯一耐えられる手（例: $-0.4$）として同じ局面に戻す手を選び続ける。
- **AIの記憶不在**: 静的盤面単体では対局履歴を認識できないため、双方が「最善」と信じて永久に往復を繰り返してしまう。

### 1.2 解決方針
対局結果（勝敗ルール）を強制変更するのではなく、探索・指し手選択処理（`player.py`）において、**「すでに過去に出現した盤面へ遷移する候補手に対し、出現回数に応じて指しにくくするペナルティ関数（Repetition Penalty）」**を適用する。

---

## 2. 数理モデル

### 2.1 幾何減衰型ペナルティ関数
出現回数 $k$ に応じて評価値を $-1.0$（即死手）に向けて漸近させる：

$$V_{\text{penalized}} = -1.0 + (V_0 + 1.0) \times \gamma^k$$

- **$V_0$**: ニューラルネットワークおよびMin-Max探索が算出した本来の評価値（$-1.0 \le V_0 \le +1.0$）
- **$k$**: その候補手を指した直後の盤面（深さ1）が、対局開始から現在までに過去に出現した回数（$k \ge 0$）
  - $k = 0$: 初出局面（ペナルティなし: $V = V_0$）
  - $k = 1$: 1回目の再訪（過去に1度出現済み）
  - $k \ge 2$: 2回目以降の再訪
- **$\gamma$**: 減衰率（本仕様では **$\gamma = 0.60$** を採用）

### 2.2 本数理モデルの数学的性質
1. **絶対的下限保証**:
   $$\forall k \ge 0, \quad V_{\text{penalized}} \ge -1.0$$
   どのような $k$ に対しても絶対に $-1.0$（即死手）を下回らない。これにより、AIが「千日手を嫌がって自らライオンを差し出す」という自滅手を選択する事故を完全に防止する。
2. **単調減少性と漸近性**:
   $$\lim_{k \to \infty} V_{\text{penalized}} = -1.0$$
   ループが継続するほど評価値は $-1.0$ に肉薄し、後述の通り確率的に決着手へと移行する。

## 3. 数値シミュレーション（$\gamma = 0.60$）

| 出現回数 $k$ | 互角局面 ($V_0 = 0.0$) | 攻め側優勢 ($V_0 = 0.4$) | 劣勢局面 ($V_0 = -0.4$) | 盤上の状態・AIの挙動 |
| :---: | :---: | :---: | :---: | :--- |
| **$k = 0$** (初回) | **$0.000$** | **$+0.400$** | **$-0.400$** | 初出局面。ペナルティなし。 |
| **$k = 1$** (1回目再訪) | **$-0.400$** | **$-0.160$** | **$-0.640$** | 攻め側がマイナスへ転落。別の打開手を模索し始める。 |
| **$k = 2$** (2回目再訪) | **$-0.640$** | **$-0.496$** | **$-0.784$** | はっきりとした劣勢評価へ。 |
| **$k = 3$** (3回目再訪) | **$-0.784$** | **$-0.698$** | **$-0.870$** | 敗色濃厚（公式千日手リーチ）。 |
| **$k = 4$** (4回目再訪) | **$-0.870$** | **$-0.819$** | **$-0.922$** | 即死手に肉薄。 |
| **$k = 5$** (5回目再訪) | **$-0.922$** | **$-0.891$** | **$-0.953$** | ほぼ即死手（$-1.0$）と同等の水準。 |

## 4. 盤上の力学と意思決定メカニズム

### 4.1 攻め側の自発的打開
優勢な攻め側（$+0.4$）は、1回目の再訪（$k=1$）で評価値が **$-0.16$** に急落する。
- 攻め側に「評価値 $0.0$（互角）」や「$+0.1$（少し手堅い別の攻め筋）」の候補手が1つでも存在すれば、AIは自発的にループ手を捨てて打開手を選択する。

### 4.2 受け側の粘りと終局決着
受け側に「即死手（$-1.0$）」しか他の選択肢がない極限状態の場合：
- **$k=1 \sim 3$**: 千日手の手（$-0.64 \sim -0.78$）は即死手（$-1.0$）より圧倒的に高いため、千日手を選んで正当に延命する。
- **$k=4 \sim 5$**: 千日手の手が $-0.92 \sim -0.95$ まで落ちると、即死手（$-1.0$）との評価差が縮小する。
  - 逆温度 $\beta = 10.0$ のソフトマックス確率において：
    - 即死手が1手の場合：千日手 $62\%$ vs 即死手 $38\%$
    - 即死手が2手の場合：千日手 $45\%$ vs 即死手計 $55\%$
  - 即死手候補が複数ある実戦では、過半数の確率で「諦めて別のマスに逃げて討ち死にする（決着）」へと移行し、自然に終局する。

## 5. システム実装仕様

### 5.1 同一局面の同定（状態ハッシュ）
- **キー構成**: `(board_state_tuple, current_player, hand_p1_tuple, hand_p2_tuple)`
- 盤面上の駒配置、現在の手番、双方の持ち駒が完全一致した状態を一意のハッシュとして記録する。

### 5.2 高速履歴管理（$O(1)$ 参照）
大量の自己対局（数十万〜数百万局）を高速に処理するため、対局進行中に `collections.Counter`（または辞書）を用いて局面の出現回数を記録する：
```python
state_counts = collections.Counter()
# 局面遷移時
state_counts[current_state_key] += 1
```

### 5.3 `player.py` への組み込み
`ModelPlayer.choose_move` において：
```python
def choose_move(self, board, legal_moves, history_counts=None, gamma=0.6):
    ...
    # Min-Max探索または直接推論で evals を計算した後
    if history_counts is not None and gamma is not None:
        for m_idx, move in enumerate(legal_moves):
            next_board = board.copy()
            GameEngine.make_move(next_board, move, self.player_id)
            next_state_key = get_state_key(next_board, 3 - self.player_id)
            k = history_counts.get(next_state_key, 0)
            if k > 0:
                v0 = evals[m_idx]
                evals[m_idx] = -1.0 + (v0 + 1.0) * (gamma ** k)
```
- `history_counts=None` の場合は従来の探索と完全互換。
